01 La pile logicielle

Quatre couches, de l'interface Windows au silicium

ThorImageCAM est une application .NET. En la décompilant, on descend de couche en couche jusqu'à découvrir que le « SDK » n'est qu'un mince wrapper au-dessus d'un protocole USB texte.

.NET CameraControl.dll IHM WPF (boutons Live / Snap / Capture). Délègue tout au ViewModel.
.NET ThorImageCAMShared.dll Cœur : ThorlabsCamera + CaptureService. 93 P/Invoke vers le natif.
natif CameraLib.dll / thorlabs_tsi_camera_sdk.dll SDK ThorLabs TSI : API C SMNC_* (93) & tl_camera_* (132).
USB EP 0x02 / 0x82 / 0x83 — protocole texte ★ Le vrai point d'accès : commandes ASCII sur endpoints bulk. Rejouable partout.

02 Le protocole USB

Un protocole texte ASCII, auto-documenté

La caméra (Cypress FX3, classe vendor 0xFF, firmware résident) n'utilise pas de protocole binaire : elle expose une interface texte sur cinq endpoints bulk. On écrit une commande ASCII, on lit une réponse ASCII, et les pixels arrivent sur un endpoint dédié.

Endpoints

0x02OUTBULK10241Commandes ASCII
0x82INBULK10241Réponses ASCII

0x01OUTBULK102416OUT secondaire (inutilisé)
0x81ININTR128—Événements / statut

Framing

Buffer de 1024 octets sur 0x02 : commande ASCII, \0, padding. Réponse \0-terminée sur 0x82. Erreurs : error <code>,<message>.

Format pixel

12 bits significatifs en uint16 little-endian (2 o/pixel). Frame = largeur × hauteur × 2 = 10 027 008 o, lue en chunks de 16 384 o sur 0x83.

En hwtrig none (software), start est lui-même le déclencheur — aucune commande de trigger séparée. L'image étant une mosaïque de micro-polariseurs, le dé-mosaïquage (intensité / DoLP / azimut) se fait côté hôte.

03 Le SDK natif

Deux ABI C documentées par la décompilation

La couche .NET pilote le natif par P/Invoke. Ces signatures (toutes extraites) sont directement transposables en ctypes. CameraLib.dll (SMNC_*) est un wrapper maison ; thorlabs_tsi_camera_sdk.dll (tl_camera_*) est le SDK TSL officiel — celui qu'utilise le binding Python thorlabs_tsi_sdk.

04 Preuve

Une vraie frame, acquise via le SDK en Python

Scène du labo capturée via tl_camera_* en ctypes, puis affichée (montage optique, câbles, un réseau en haut à droite). La chaîne complète fonctionne : open_sdk → discover → open_camera → set_exposure → arm → software_trigger → get_pending_frame.

C'est cette même séquence que le pilote pyusb rejoue directement au niveau USB, sans dépendre d'aucun binaire ThorLabs.
